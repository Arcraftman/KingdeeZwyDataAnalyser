# 项目边界

本仓库保留一个根目录，按**可独立运行的客户端、服务和库**划分。根目录的两个构建清单分别服务于 Electron 和 Python；目录名不表示运行时依赖关系。

| 目录 | 归属 | 负责 | 不负责 |
| --- | --- | --- | --- |
| `electron/` | 桌面客户端 | 窗口、交互、报表展示；主进程调用本机 API | 账无忧请求、财务规则、读取远端会话 |
| `python/data_analyser/` | 当前财务服务 | 登录、账套注册、只读白名单、财务快照、DeepSeek；兼容旧 Excel 的模板与 XML | Electron 界面 |
| `cpp/` | 独立 C++ 迁移模块 | 可独立构建和测试的确定性转换与校验 | 登录、网络、密钥、界面；目前没有接入线上刷新 |
| `excel/` | 旧 Excel 客户端 | VBA 刷新适配器 | 财务数据读取和金额规则 |
| `config/` | 财务服务配置 | 允许读取的远端接口定义 | 客户端可修改的业务数据 |
| `scripts/` | 本地开发和安装 | 启动、依赖安装、旧 Excel 宏安装 | 财务业务逻辑 |
| `tests/` | Python 行为与接口回归 | 快照、只读约束、Excel 兼容行为 | C++ 单元测试；后者在 `cpp/tests/` |

## 数据流

```text
Electron 界面
  → preload 中明确列出的操作
  → Electron 主进程
  → 带本地令牌的 127.0.0.1 服务
  → 账套身份校验与只读请求
  → 一次财务快照
       ├─ /snapshot.json → Electron（JSON，报表数据）
       └─ /snapshot      → 旧 Excel（Excel 2003 XML）
```

- `/health` 返回协议版本和只读状态；`/companies` 只返回已启用账套的编号和名称。
- 两个快照端点调用同一个 `collect_snapshot`。财务金额、凭证平衡、账套身份与辅助余额核对只有一个生产实现。
- Electron 渲染进程不读取文件或访问账无忧网络；主进程只读取本地服务令牌。远端会话、账套注册表和 DeepSeek 密钥由服务负责。
- `runtime/`、`http_sessions/`、`node_modules/` 和构建目录是本地状态或生成物，不进入 Git。

## C++ 迁移规则

`cpp/` 当前只有独立的 XML 序列化练习。它尚未参与正式刷新，因此 Python 的财务规则仍是唯一生产实现。移植规则时，先保持输入输出契约不变，用同一份样例比较两种实现；切换后删除或停用旧规则，避免两份计算长期并存。C++ 将来可以由 Python 服务调用，也可以取代服务实现；Electron 只依赖上面的本机 API。
